# Partner pannel — бизнес-требования

Версия 1.1 · 09.09.2026 · **Согласовано пользователем. Разработка разрешена.**

Изменение 1.1 (09.09.2026): контакты Telegram/WhatsApp для MVP не предоставляются — значки статические, без перехода и без подписи об ожидании (CONTACT-01, CONTACT-02, AC08). Вход для MVP ограничен парой `klim` / `klim`; поведение эталона входа (AC02, AUTH-04) отложено.

Решение запуска: React + TypeScript + Vite, отдельный Node.js-сервер для AI. Рабочие допущения: новая вкладка для партнёров, 3D-рендеры, клиентское УТП, тексты S05/S06 из этого БТ. Доступ к AI остаётся данными к заполнению; контакты для MVP не предоставляются.

Порядок: согласовать БТ и стек → утвердить версию 1.0 → начать реализацию. До утверждения создаётся только документация. Изменения требований фиксировать в БТ до разработки соответствующей функции.

## 1. Цель и исходники

Витрина сервисов партнёров VTB Kazakhstan: клиент входит в локальный демонстрационный VTB Business, изучает сервис и предложение, нажимает «Подключить» и переходит на сайт партнёра. Переход не означает оформление договора или активацию услуги.

- Рабочая папка: `C:\Users\User\Desktop\Работа\Ecosystem\pannel`.
- Репозиторий: `Klim2007/Partner-pannel`.
- Основная копия БТ: `docs/BT.md` в рабочей папке. Выдаваемая в чате копия должна соответствовать ей.
- `Front page 1.txt` содержит эталон входа: <https://ib.vtb-bank.kz/ru/html/login.html>. Страница открыта и визуально изучена 09.09.2026.
- `mvp.pptx`, слайд 1: шесть названий, порядок, сетка 3 × 2, четыре ссылки. Описания и условия представлены шаблонными подписями.
- `одна из экранных форм VTB Business.pptx`, слайд 1: скриншот внутреннего интерфейса для ориентира по оформлению. Реальные имена, организации, счета и платежи из него в демонстрацию не переносить.

Приоритет: последние решения пользователя → согласованное БТ → эталон входа для стартовой страницы → MVP для каталога. Текущий этап — localhost; публикация сайта и интеграция с реальным интернет-банком в объём не входят.

## 2. Страница входа

**AUTH-01.** Воспроизвести Front page визуально полностью. Сохранить логотип, композицию, цвета, шрифты, размеры, отступы, тени, тексты, объявления, ссылки и подвал. Ничего не добавлять и не удалять. Маскот и новые контакты находятся только после входа.

В изученном эталоне присутствуют:

- «Памятка по безопасности», «Программное обеспечение», «Инструкции», «Демо-версия»;
- логотип VTB, RU / EN / KZ;
- поля «Пользователь», «Пароль», значок виртуальной клавиатуры;
- «ВОЙТИ», «Забыли пароль?»;
- лента объявлений и подвал с телефонами, электронной почтой и копирайтом банка.

До вёрстки сохранить полный эталон страницы и ресурсы на согласованную дату. Сравнивать при одинаковом размере окна, масштабе 100%, языке RU и состоянии элементов. Предложенный основной размер — 1440 × 900; полный контент проверять прокруткой. Динамическую ленту в локальной копии закрепить по эталону. «100%» означает визуальное сравнение всех блоков, а не только наличие полей входа.

**AUTH-02.** Демо-пользователь `klim`, пароль `klim`, регистр учитывается. Успешный вход открывает панель. Пустые/неверные данные не дают доступ, появляется понятная ошибка. Enter отправляет локальную форму, пароль скрыт.

**AUTH-03.** Данные обрабатываются локально, не отправляются на банковский сайт. `klim` / `klim` — демонстрационная проверка, которую позднее заменит серверная авторизация. Прямой переход на панель требует демо-сессии; выход завершает её и возвращает на вход.

**AUTH-04.** Все элементы эталона сохраняются. Поведение RU/EN/KZ, виртуальной клавиатуры, «Забыли пароль?» и «Демо-версии» требуется уточнить перед реализацией. Реальное восстановление банковского доступа не предусмотрено.

## 3. Панель и карточки

**PANEL-01.** Заголовок из MVP: «Программы партнеров для вашего бизнеса». Русский язык, фирменные синие/голубые цвета и белый фон. Допускаются улучшения дизайна панели в пределах этого БТ.

**PANEL-02.** На широком экране — три карточки в ряд, два ряда, порядок из MVP. Предложение: две и одна колонка при сужении окна. Сетка и отступы должны поддерживать длинные названия без обрезки.

**CARD-01.** Под названием каждого сервиса находится собственный визуал в 3D-стилистике. Название видно постоянно. Единые свет, материалы и ракурс объединяют шесть иллюстраций.

**CARD-02.** При наведении на визуал появляется слой: краткое описание, преимущества, предложение/условия и «Подключить». Исключение — страхование, см. S05. Переход указателя к тексту и кнопке не закрывает слой. Карточка не меняет размер при раскрытии; текст читается целиком.

**CARD-03.** Для каждого сервиса создать индивидуальный визуал в 3D-стилистике: при наведении он плавно увеличивается и слегка наклоняется, а поверх него анимированно появляются описание, условия и кнопка «Подключить»; для «Страхования» отображается только общее УТП без кнопки и перехода. Раскрытие также по фокусу клавиатуры и по нажатию на сенсорном устройстве, закрытие по Escape или нажатию вне карточки. Учитывать настройку уменьшения движения.

**CARD-04.** «Подключить» открывает соответствующий URL. Предложение: новая вкладка с сохранением витрины. Интерфейс не сообщает, что услуга активирована. Для пяти сервисов с переходами адреса должны быть заполнены; у страхования переход намеренно отсутствует.

**CONTENT-01.** Для S01–S04 подготовить и согласовать описание, преимущества и предложение/условия. Наличие URL в MVP не подтверждает банковское партнёрство или льготный тариф. Цены и скидки не выдумывать. Исходную подпись «УТП для партнера» предлагается трактовать как выгоду для клиента; требуется согласование.

**VISUAL-01.** Предложение: оригинальные растровые 3D-рендеры с общим стилем, оптимизированные для браузера. Вращаемые 3D-модели/WebGL не обязательны для такого вида. Создать иллюстрации и маскота на этапе реализации после утверждения БТ.

## 4. Быстрая связь

**CONTACT-01.** На панели разместить значки Telegram и WhatsApp с надписью «Быстрая связь с Банком», компактным блоком под сеткой. Для MVP значки статические: без ссылки, без перехода, без подписи об ожидании. Ссылки не добавлять, пока контакты банка не согласованы отдельно.

**CONTACT-02.** Контакты для MVP не предоставляются. Телефон из подвала не считать номером WhatsApp. Когда контакты согласуют: адреса хранить в настройках сервера (переменные окружения), открывать только подтверждённые адреса банка по https, значки делать ссылками.

## 5. VTBшка — настоящий AI

**AI-01. Решение пользователя:** уже первая версия использует настоящий AI через бэкенд, не подменяется готовыми ответами.

**AI-02. Образ.** Предложение: дружелюбный компактный 3D-персонаж с округлым бело-синим корпусом, голубыми акцентами и выразительным лицом. Имя — «VTBшка». Исходный логотип VTB сохраняется отдельно.

**AI-03. Интерфейс.** Маскот на панели открывает чат. Предложение: правый нижний угол; чат не закрывает действия карточек. Предусмотреть ввод/отправку сообщения, историю текущего диалога, ожидание ответа, ошибку, повторную попытку и закрытие. Предложение: после выхода из демо-сессии историю очищать.

**AI-04. Ответы.** Помощник объясняет использование VTB Business и витрины, помогает найти раздел или нужный шаг. Опирается на утверждённые инструкции; прикладывает ссылки на использованные источники. При отсутствии подтверждённого ответа сообщает об этом и предлагает обратиться в поддержку. Нужны примеры: навигация по витрине, подключение партнёра, поиск инструкции по работе с VTB Business.

**AI-05. Границы.** Не выполняет банковские операции, не запрашивает пароли/коды, не выдаёт предположения за инструкции банка. Ключ модели хранится только на сервере. Запросы содержат вопрос и необходимый контекст из базы знаний, без автоматической передачи данных банковского скриншота.

**AI-06. Сервер.** В первый этап включить минимальный серверный обработчик AI, подключение выбранного провайдера, поиск по базе инструкций, ограничение размера запросов, обработку таймаутов/лимитов и ошибок. Для localhost с облачной моделью требуется интернет. Провайдера, модель, доступ и состав базы знаний согласовать до реализации интеграции; ключи не включать в БТ или Git.

## 6. Выбор технологий

Для начала реализации принят рекомендованный вариант A: **React + TypeScript + Vite**. Альтернативы сохранены для справки.

| Вариант | Состав | Когда выбирать |
| --- | --- | --- |
| A — рекомендуется | React + TypeScript + Vite | Локальная интерактивная витрина и отдельный сервер API/AI |
| B | Next.js + TypeScript | Фронтенд и серверные обработчики AI в одном приложении |
| C | Vue 3 + TypeScript + Vite | Компонентная альтернатива React и отдельный сервер API/AI |

Это проектная рекомендация. Возможности инструментов: [Vite](https://vite.dev/guide/), [Next.js](https://nextjs.org/docs), [Vue](https://vuejs.org/guide/introduction.html). Для A/C сервер можно сделать на Node.js + TypeScript; конкретный серверный фреймворк выбрать после фронтенда. Для B использовать серверные обработчики Next.js. Точные версии зависимостей закрепить при начале работ.

Предложение: собственные стили для точного повторения входа; компоненты карточек/чата; локальные изображения. Публичный SEO-сайт, полноценная БД и админ-панель не требуются в первом этапе.

## 7. Возможность развития бэкенда

**API-01.** Данные отделить от компонентов. Каталог сначала может читаться из локального источника через адаптер; затем HTTP-адаптер заменяет его без переписывания карточек. AI с первого этапа обращается к серверу.

**API-02.** Модель сервиса: `id`, `name`, `provider`, `description`, `benefits[]`, `terms`, `offer`, `imageUrl`, `imageAlt`, `connectUrl`, `displayOrder`, `actionType`. Для S05: `connectUrl=null`, `actionType=informational`; для остальных — внешний переход. Отдельно: контакты, сессия, сообщения и источники AI.

Предварительные контракты:

| Метод и путь | Назначение | Этап |
| --- | --- | --- |
| `GET /api/v1/services` | Каталог и контент | Контракт сейчас, HTTP при развитии |
| `GET /api/v1/contacts` | Контакты | Контракт сейчас, HTTP при развитии |
| `POST /api/v1/auth/login` | Создание серверной сессии | Будущий бэкенд |
| `GET /api/v1/auth/session` | Проверка серверной сессии | Будущий бэкенд |
| `POST /api/v1/auth/logout` | Завершение серверной сессии | Будущий бэкенд |
| `POST /api/v1/assistant/messages` | Вопрос, ответ и источники AI | Первая версия |

**API-03.** Предусмотреть загрузку, пустое состояние, недоступность API и повтор запроса. Адрес API — в конфигурации. Серверная авторизация позднее проверяет доступ независимо от фронтенда. Демо-вход не используется как производственная защита AI API; первая серверная версия предназначена для локального запуска.
